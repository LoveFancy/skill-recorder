# v11.2 当前交互规则（优先于下方历史评审）

本轮仅调整设计。首页录制界面保持原样，顶栏统一为“原始素材确认 → 深度分析 → 生成”。

| 阶段 | 主要内容 | 主要动作 |
| --- | --- | --- |
| 原始素材确认 | 忠实、粗略的原始操作记录，素材默认收起 | 确认并深度分析 |
| 深度分析 | 结合意图、已确认操作与能力补证；必要时问业务问题；形成完整流程、规则、变化内容及缺口 | 确认并生成 |
| 生成 | 基于已确认分析生成 Skill / SOP，可读预览与使用依赖 | 确认并保存 |

深度分析是有明确产物的一个阶段。能力匹配/查询进度、问卷、完善结果只是同页状态，不加子导航。不需要问题时直接展示分析结果；回答提交后继续完善分析，不能跳到生成。完整分析结果可原位编辑，也可补充说明后重新分析。未知项显式保留，用户可确认带缺口的分析并生成草稿。

默认界面只保留目标摘要、流程正文、必要规则和一个主要按钮。查询日志、来源、工具用途按需展开。不显示思维链。分析页展示“本次分析使用”的真实工具；生成预览分别展示“使用此技能需要”的依赖，不将登录或工具发现当作实际调用。

每个阶段可以回退、修改及显式重做。查看或点击阶段导航只恢复已有状态，不启动调用、不代替确认；尚未形成的结果展示对应进度/未开始状态，不提供越级生成。原始记录/意图改变使相关深度分析与生成失效；回答/证据变化使相关分析及生成失效；仅改变输出格式只使生成失效。旧回答、已验证证据及旧成果保留，受影响内容显示需要更新。生成只接受当前已确认且未过期的分析。取消与失败保留检查点，继续/重试必须显式触发；无法确认持久化时不得宣称内容已保存。

深度分析等待态采用左右布局：左侧统一列出实际使用的工具和素材，右侧根据 Claude 结构化进度 JSON 逐条更新动态时间轴，应用补充实际运行和调用异常；模型报告与工具核验记录分开。工具名称只出现一次，不在每个工具卡片中重复过程。时间轴展示动作、状态和简短结果，不展示思维链；长记录内部滚动，回看不强制跳到底部。

补证成功、跳过、失败分别使用实际证据和工具摘要；跳过路径不显示邮箱补充成功。自动只读查询仍必须满足下方 v11.1 的实际授权、账号、范围、隐私与证据关联约束。受控业务 MCP 运行仍是待实施能力。

验收：有问题→回答→完善结果→确认→生成；无问题→结果确认→生成；未知→带缺口结果→确认生成草稿；回退修改→标记失效→显式更新→重新确认。任一路径都不能因页面跳转或工具返回而跳过确认。

# v11 产品评审：让用户只处理业务内容

本版面向非技术用户，替代 v10 的页面流程。设计稿，不代表已经实现。

## 评审结论

原方案的主要负担不在控件数量，而在把后台工作拆成了用户任务。用户回答问题后，还要理解“材料确认、增强、候选、审核、生成准备、目标架构、计划”等概念，同一条规则重复确认，难以判断下一步与完成标准。常驻解释文字又放大了这种负担。

保留三个一级阶段：**分析 → 澄清和补充 → 生成**。用户理解为：**看看操作 → 回答问题 → 检查并保存**。

第二阶段取消全部子导航、材料提交预览页和独立事实审核页。问题、其他输入和可选附件在同一页面；点击“生成草稿”提交并启动后台整理，进入第三阶段等待与预览。最终预览承担内容审核，确认并保存是明确的用户批准动作。生成本身仍只是候选。

## 逐处评审与调整

| 原设计负担 | v11 调整 | 为什么 |
| --- | --- | --- |
| 录制前重复询问任务与最终效果 | 只保留产出类型和一句话任务目标，框内麦克风 | 避免让用户写需求文档 |
| 大标题、日期、状态占据首屏 | 顶部三阶段，下方约 40px 工具栏 | 给业务内容留空间 |
| 时间线长期占据大块区域 | 默认一行“录制材料”；展开保留三行时间轴 | 用户需要核对时再看证据，不丢弃原能力 |
| 每页都有后端与环境信息 | 分析/澄清/生成正常状态收进设置；录制页保持原有四行状态 | 不要求用户理解 Agent/API 切换 |
| 第二阶段有三个子阶段 | 一个连续问卷页面，无二级导航 | 用户只需回答业务问题 |
| 填答后再次确认统一材料 | “生成草稿”提交当前可见回答及附件 | 避免对同一输入重复确认 |
| 单独增强等待与增强完成页 | 自动进入生成等待；完成展示可读预览 | 系统内部阶段无需逐次点击 |
| 逐条 Evidence/Claim 审核 | 最终预览展示业务规则；“查看依据”按需打开 | 确认内容而非理解数据结构 |
| 生成准备、计划、正文多次切换 | 一份可读预览，支持原位修改 | 用户有一个清楚的完成点 |
| 大面积目标平台卡片墙 | 沿用录制前偏好，默认通用技能；其他格式折叠 | 不把格式选择变成必修课 |
| 不确定与技术异常混杂 | 不确定保留待补充；配置异常给原因和修复按钮 | 不把系统责任推给业务用户 |
| 设置中反复解释隔离和快照 | 一行状态＋必要开关；机制放到“来源与连接详情” | 简化日常操作，保留按需诊断 |
| 总览把分支都排列成必经流程 | 主流程 10 张示意，其余状态与设置折叠 | 线稿数量不等于流程步骤 |

第 10 张是保存成功；等待态无用户决策。录制结束后，正常路径的主动操作是：在分析点继续、回答问题后点生成草稿、预览确认并保存（另有系统文件选择器）。不以减少线稿张数代替减少用户操作。

## 三阶段交互约定

### 1. 分析

停止录制后保存材料并开始原有分析；配置或隐私检查需要处理时就地提示。只显示当前进度与真实耗时，不铺开后台调用清单。分析结果优先显示业务摘要和步骤，“修改”“查看”是次要操作。

材料条、展开的三行时间轴与正文使用同一左右边界。压缩的是分析/日期/重新分析工具栏，不把时间线永久替换为数量标签。悬停查看截图、语音文字、浏览器动作继续保留。

“继续”表示用当前分析进入下一阶段，不自动批准未证实的操作结果。

### 2. 澄清和补充

从分析页点“继续”后，先在第二阶段原位显示 Agent 强化分析的等待状态：标题“正在分析还需要补充什么…”，一行当前处理状态、真实耗时，以及“返回分析”“取消分析”。该状态必须出现在主流程总览，不作为隐藏分支。完成后自动替换为问卷，无问题则显示可以直接生成。返回分析保留后台任务；取消才停止，后续显式重试。

首次进入自动依据用户目标、前序分析和已有材料整理问题；返回复用结果，失败或输入改变后明确重试/更新。分析负责读取原始录屏，整理问题不再完整重跑视频理解。

默认展示 1–3 个必要业务问题；这不是隐藏关键缺口的硬上限，其他未解决事项保存到草稿。每题提供有依据的选项、“其他”和“暂不确定”。不默认作答。其他输入原位展开。适用范围、红框含义、技术后端不再成为独立必填项。

页面底部只有一个主动作“生成草稿”。“＋ 补充说明或文件”为次要入口。已答自动保存为草稿；点击主动作后才固定本次输入并处理。无需额外材料确认页。

没有问题时显示“信息已经够用了”，直接提供生成按钮，不凑问题、不强制确认。暂不确定或未答可以生成草稿，缺口持续出现在预览和文件中。用户选择其他/未知不等于系统可以推断业务规则。

新增冲突只就地追加相关问题，保留原答案；不能循环要求完整重答。用户可选择保留缺口，避免无限追问。附件上传失败就地提示，允许移除附件继续。

### 3. 生成

点击生成后自动串联输入冻结、检查、补充整理、计划和正文生成，UI 只显示当前真实状态与耗时。中间结果存储、恢复、后端隔离和结构校验继续存在。

完成后直接显示易读预览：适用范围、步骤、关键规则、待补充项。所选 SOP/Skill 沿用录制前偏好；暂不确定时使用一个简短选择弹层。通用 Skill 为默认格式；专用目标放在“其他格式”，不能把本地专属工具直接写进通用格式。切换目标只重建受影响生成内容。

最终“确认并保存”确认用户看到的内容，并打开系统保存对话框。草稿按钮明确为“确认并保存草稿”。只有写入成功才显示已保存；取消/失败留在预览。生成完成、页面跳转、模型自报不构成批准。保留查看文件原文和来源的入口，但默认不展示代码。

如模型补充了无法追溯或未经确认的事实，该内容必须标为待确认或阻止纳入固定规则；已核验的来源或用户规则才能成为正式规则。current 时间信息不能冒充 at-recording 事实。最终审核移到了预览，不是取消审核。

## 文案与布局规则

- 每页一个主按钮；次要操作用文字入口。必要的重试/取消保留。
- 正常页一个标题，最多一行必要说明。技术细节不做常驻提示。
- 面向用户使用“回答、文件、内容、待补充、保存”；内部 task-package、manifest、snapshot、claim、architecture、版本号不直接出现在主流程。
- 错误写“出了什么问题＋下一步怎么做”；堆栈与脱敏诊断按需展开。
- 阶段导航表示位置，不能因点击而批准、重新运行或跳过必需校验。尚未完成的阶段禁用或说明缺少什么；线稿导航为状态展示。
- 1200×900 为评审画布；实现时正文单层滚动，底部动作固定但不遮挡内容，小窗口不靠缩小字号适配。
- 模型处理不显示假进度或思维链。正常后端藏在设置，运行详情仍可查看实际调用来源。
- 不加入费用控制、自动发送、Replay 或 Scout 执行承诺。

## 设置与例外

设置继续分为通用、浏览器插件、AI 模型、Agent 能力、语音转写、隐私保护。首页只有状态和设置入口。

Agent 默认专用环境、继承可核验全局能力目录。开关只影响本应用；隔离、来源复核、主动连接检查仍按原约束执行。新增设计允许 Agent 在本应用已启用、账号及只读权限已核验、已有授权范围内，使用匹配的业务 MCP 补充本次录制细节。工具不可用时继续使用录制内容或由用户提供材料，来源在预览可查看。现有实现尚未接通这条自动业务读取链路。主动 MCP 检查可能启动程序并要求登录，需在详情中说明。

API 技术字段集中在折叠配置；已保存与连接可用区分。自动策略只在本地未安装等既定条件下回退，认证失败不静默切换。

未保存设置离开、隐私失败、生成取消、保存失败仍需实现，就地提示或原生对话框即可，不为每个变体新增必经产品页。输入变化保留旧结果，只提示一个“更新草稿”动作；同会话串行与检查点恢复继续按内部契约实施。

## 线稿验收与实施边界

本次输出 10 张主路径示意，另外展示同页问卷状态、语音、可选详情、故障恢复和设置；这些分支在总览折叠。图中文字和业务数据为示例，按钮用于导航到状态，不执行真实录制、查询或保存。

需验证：三阶段名称统一；第二阶段无二级阶段导航；默认不展示技术后端；未知不默认变成规则；预览前不得显示正式成果已确认；所有源图、索引与总览一致且无正文裁剪。

应用代码尚未按本版改造。旧技术方案的内部数据、可靠性和权限约束继续有效；与用户页面步骤冲突处以 v11 为准。

## 录制页保留约束

按最新确认的真实界面保持录制页布局，包含圆形录制控件、计时器、录制范围卡、语音旁白、采集说明、记录入口、四行状态和快捷键提示。录制前后只按真实状态更新内容，不换成宽屏新首页。流程简化集中在分析、澄清和补充、生成。目标确认弹窗从原圆形按钮/快捷键进入；取消不开始采集。

## v11.1 能力匹配与补充进度

[能力补充状态总览](v11/board-capabilities.png) 展示同一等待页的状态变化，不新增子阶段。

用户在分析页点继续后，Agent 先根据前序分析识别邮箱、浏览器、业务系统等应用及具体缺口，再匹配当前实际启用的能力。匹配成功且允许读取后，自动在当前范围内补充细节，再生成必要问题。默认文案用“正在通过邮箱补充细节”，卡片保留“邮箱 MCP”以说明正在使用的连接。只显示与本次任务相关的能力。

| 状态 | 默认显示 | 后续 |
| --- | --- | --- |
| 能力匹配中 | 正在匹配可用工具；邮箱 MCP · 检查中 | 核验账号和读取能力 |
| 读取中 | 邮箱 MCP · 已启用、已登录；正在查找本次邮件 | 显示真实调用进度与耗时 |
| 补充完成 | 已补充邮件主题、收件人和附件名称 | 自动整理问题，不额外要求确认进度 |
| 没有可用能力 | 使用录制内容 | 保留缺口；不凭空声称使用了 MCP |
| 登录/权限失效 | 需要登录或没有读取权限 | 去登录/设置，或先用录制内容继续 |
| 查询失败/无结果 | 对应的简短原因 | 重试或先继续，保留已验证材料 |

“已登录”只在连接器提供可验证认证结果时使用；本地 Claude 已登录、发现工具、tools/list 成功均不能单独证明邮箱账号有读取权限。无法获知认证状态时显示“已连接”“可读取”或“待检查”，不得造出已登录状态。能力匹配依据实际工具 schema、数据对象、账号与用途，不以名称含“邮箱”作为充分依据。

只读自动补充是新增设计范围。不能把已经打开的工具开关当成任意数据访问或发送授权；默认只在已获授权、已选择连接和任务范围内运行。无法落实只读限制或账号身份时不调用，给出可跳过提示。启用文案说明用途为读取相关内容补充录制，发送、删除、标记、修改等动作均不属于本阶段。

查询优先使用录制中已有消息 ID；否则结合时间范围、主题、联系人等窄化定位。详情展示真实范围和账号提示，线稿中的“前后 5 分钟”为示例而非固定规则。不得全量扫描邮箱；没有可靠定位时保留缺口，多候选不可猜选。需要扩大到既有授权范围之外时先说明新范围并获取对应授权，不静默扩张。

进度展示以最新技术方案 §5.9 为准：Claude 通过 report_progress 提交 JSON，应用校验保存并更新展示；实际工具调用和阶段完成状态仍由应用核验。显示用途与已完成动作，不展示模型思维链。能力发现完成不能伪装成工具开始调用，工具返回成功不能直接标记“事实已确认”。查询结果需校验关联、脱敏后入库，并保留来源、查询时间与 temporalScope，仍按最终预览确认机制处理。

问题去重：已查到的主题/附件等具体事实不再重复询问用户；“本次发给张某”不能推出“以后都发给张某”，未来的联系人选择规则仍可作为业务问题。完成摘要只在实际取得并核验材料时显示，未运行/失败的分支不显示“已补充”。

登录失效或未匹配不阻断基本生成，继续时明确待补充。API 后端或能力隔离不支持业务读取时，同样显示“使用录制内容”，不得暗示继承了本地 MCP。运行绑定能力版本；页面返回复用现有运行，取消停止后续调用并处理迟到事件，避免重复查询。结果入库沿用增量隐私处理和检查点机制。

设置/运行适配所需改造仍是待实施工作：新增受控只读 MCP 调用、权限和账号核验、可观察事件、材料关联与增量存储。本轮只更新线稿和设计说明，未实际查询任何邮箱。
