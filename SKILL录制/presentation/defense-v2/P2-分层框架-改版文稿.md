## 一、页面主张

三个用词上的决定：

| 决定 | 原因 |
| --- | --- |
| 「上移」替代「前移」 | 前移容易被读成时间上的提前，实际是沿技术栈向上移动 |
| 「关注点」替代「瓶颈」「问题」 | 不与后页「卡点」抢词；这里是趋势判断，后页是问题定义 |
| 用「四层栈」而不是「四层架构」 | 明确为本课题的观察框架，避免被当作行业标准分类追问 |

## 二、四层栈（上屏主体）

自下而上，越往上越靠近企业与个人；本课题落在最上面两层，且各有产出：

| 层 | 这一层解决什么 | 现状 | 本课题产出 | 例 |
| --- | --- | --- | --- | --- |
| **L4 表达层** | 人如何把自己的工作、需求表达成 AI 能执行的形式：流程、判断与例外都要说清楚 | 本课题关注 | **Skill** | Prompt · Skill · SOP 的编写 |
| **L3 企业上下文（Context）** | 业务数据、客户数据、流程数据等企业数据资产，决定 AI 是否真的了解这家公司 | 本课题补充 | **SOP · 使用手册** | 企业级数据治理 · 金融中台 |
| **L2 Agent 层** | 工具与编排的执行骨架，是 AI 落地的入口 | 相对成熟 | — | WorkMate · 数字分身 · AgentFactory |
| **L1 模型层** | 理解与推理的通用能力，是 AI 落地的基石 | 相对成熟 | — | DeepSeek · GLM · Kimi |

- L1 / L2 用浅灰底 + 「相对成熟」，表示已就位；
- L3 用浅蓝底 + 「本课题补充」，表示企业在做数据治理，本课题用 SOP 与手册补上流程性知识；
- L4 用主色描边 + 「本课题关注」，是整页焦点，产出可执行的 Skill；
- 左侧竖线渐变（下淡上深）加向上箭头，承载「关注点上移」。

与 P3 的衔接：P3 的「供给主体」对应 L3（谁提供知识），「转化通道」对应 L4（怎么传过去）。术语不重复造。

## 四、讲稿（约 100 秒）

> 落地一个 Agent，可以按四层来看。
>
> 最下面是**模型层**：DeepSeek、GLM、Kimi 这些模型，能力和可用性都在稳步往前走，通用任务上已经够用。
>
> 往上是 **Agent 层**：WorkMate、数字分身、AgentFactory 这类平台，把工具调用、任务编排、执行回传这些骨架越做越完整，接企业系统的路径也清楚了。
>
> 再往上，是**企业上下文**：业务数据、客户数据、流程数据。这一层企业其实一直在做——企业级数据治理、金融中台，本质上就是在把数据攒起来、治理干净。
>
> 最上面是**表达层**：即便前三层都到位，还得有人把自己的经验说成 AI 能执行的形式。这一步没有平台能替人完成，而且要求会做的人同时会写。
>
> 所以真正要解决的不在模型，也不在 Agent 运行时，而是上移到了最上面这两层。本课题做的正是这一层——让会做这项工作的人，不必先成为 Skill 编写者。
>
> 接下来把这条通道拆成两段看：谁提供知识，怎么传过去。

## 五、判断口径

- 各层「逐步完善」「正在建设」是趋势判断，不表示问题已全部解决；实现状态以 P11 为准。
- 平台与模型名称仅作团队当前接入示例，不上版本、份额与评测结论。
- 「上移」指关注点沿技术栈向上移动，不是时间意义上的提前出现。
- 四层框架为本课题自拟的观察框架，不作为行业标准分类引用；若被问「这是哪套标准」，回答：不是标准分层，是本课题用来定位问题的一组环节，底层两层借用通行说法（模型层、Agent 层），上层两层是本课题的表述（企业上下文、表达层）。

## 六、被追问时的补答

| 问题 | 回答 |
| --- | --- |
| 为什么把上下文单列一层？ | 模型和 Agent 都通用了，但企业的流程、口径、例外、权限不会自动进去；企业级数据治理与金融中台做的是同一件事 |
| 表达层和上下文层什么关系？ | 上下文解决「给什么」，表达解决「怎么给」；前者是知识资产问题，后者是传递损耗问题 |
| 表达层能不能也靠平台解决？ | 平台能降低门槛，但「这次为什么这么判断」「哪些算例外」只有当事人能说清；本课题做的就是把这部分从"说"变成"做 + 澄清" |
| 瓶颈是不是会继续上移到组织层？ | 有可能，也属于后续演进；本课题先解决最贴近一线的表达层 |
