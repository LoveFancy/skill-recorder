# 录制产物设计：SOP、Skill 与使用手册

日期：2026-10-17  
状态：2026-10-17 已落地首版实现（工作区源码，尚未发布）。SOP、使用手册独立生成/审核/导出链路已接入；Skill 复用计划链路并补充映射说明。内容质量和业务可执行性不因机制测试通过而视为验证完成。

新增设计：[v12 生成与发布交互稿](design/skill-generation-wireframes/index-v12.html)及本文 §11；第四步发布与分享尚未实施。

关联：[总体流程](skill-pipeline-overall-plan.md)、[录制后增强方案](post-recording-enrichment-and-replay.md)、[Claude 执行层](claude-task-session-design.md)。本文是三类产物的职责与生成规则来源；旧文中统一要求 Skill/SOP 转成运行时查询、依赖目标能力或提出技能计划的描述，按本文分流。

## 1. 产品约定

**只有生成 Skill 才进行执行方式“翻译”；SOP 和使用手册保留实际界面操作方式。**

| 维度 | SOP | Skill | 使用手册 |
| --- | --- | --- | --- |
| 读者 | 完成具体任务的操作者 | 执行任务的 Agent | 了解、学习某个产品的使用者 |
| 核心问题 | 这项任务应该怎样操作 | 如何用目标环境能力重复完成业务目标 | 已覆盖的功能在哪里、怎样使用 |
| 组织方式 | 按任务先后顺序 | 按可复用业务流程及工具调用依赖 | 按功能、场景和导航层级 |
| 是否翻译为 MCP/CLI | 否 | 是，保持业务语义等价 | 否；若录制本身是 CLI，则保留实际命令 |
| 是否需要技能计划 | 否，直接审核操作说明 | 是，审核泛化和工具映射计划 | 否，审核目录与覆盖范围 |
| 是否依赖目标能力快照 | 否 | 项目专属工具映射需要 | 否 |
| 单次录制的产出边界 | 已覆盖任务的 SOP | 已知规则范围内的技能或技能草稿 | 已覆盖功能的手册章节 |

共同原则：录制中的成功、失败和人工补充分别标注；未观察到结果不能写成已成功。可去除无关操作和合并重复动作，但需保留必要纠错、分支及结果证据。用户确认的新标准步骤可以进入文档，但必须标注补充来源，不伪装为录制事实。

例如录制“通过网页回复邮件”：SOP 保留打开邮件、点击回复、填写、发送及结果；Skill 可在工具确实可用且支持回复线程语义时转换为邮箱 MCP；使用手册将其整理为“邮件回复”功能章节，不能扩展为未演示的邮件规则管理教程。

## 2. 当前基础与新增范围

本节表格记录设计前基线；实际实施状态见 §10。

| 能力 | 源码基础 | 本设计调整 |
| --- | --- | --- |
| 录制分析 | `common/analysis.ts`、`electron/describer/`，包含意图、步骤、证据和浏览器事件引用 | 保持产物中立，移除“只为 Skill 提供素材”的提示词倾向 |
| 深度分析 | `common/enhancement.ts`、`electron/enrichment/`，有缺口、审核、来源与时态分类 | 按产物决定必要问题，不给 SOP/手册追加自动化问题 |
| 生成偏好 | `requestedOutput` 当前为 sop/skill/undecided | 新增 manual，并保留 undecided；与目标 architecture 分开 |
| Skill 计划与生成 | `SkillPlan`、`BuiltSkill`、`electron/skillbuilder/` | 复用；补充映射语义和正文一致性校验 |
| SOP | 现有 `analysis.md` 是分析记录，尚非完整 SOP 生成器 | 新增结构化文档、预览和导出 |
| 使用手册 | 无独立生成链路 | 新增覆盖范围、目录审核、功能章节及导出 |

本期止于内容审核与文件导出。不新增实际业务试跑、自动安装 MCP、账号授权或浏览器回放执行器；Skill 的执行验证继续为未验证。

## 3. 用户流程

1. 录制前可选择 SOP、Skill、使用手册或暂不确定，填写任务目标。选择是偏好，录制后仍可调整。
2. 基础分析还原实际操作，用户纠错确认。所有产物共享同一份事实底稿。
3. 按当前产物识别必要缺口。证据已充分可直接审核并继续，不强制使用 MCP 或执行深度分析；需要补证时沿用现有授权、只读和脱敏边界。
4. 在生成页选择产物及对应模板：
   - SOP：整理步骤 → 编辑预览 → 保存。
   - Skill：选择目标环境 → 草拟技能计划 → 用户确认 → 生成预览 → 保存。
   - 使用手册：确认读者与覆盖范围 → 草拟目录 → 用户确认 → 生成章节 → 编辑预览 → 保存。
5. 同一录制可分别生成多个产物，独立版本、独立审核，不用一个全局状态覆盖另一个产物。

SOP/手册不展示 MCP 配置和工具白名单选择。Skill 才展示目标架构与依赖缺口。手册默认“本次录制覆盖的功能”，只有用户提供足够补充材料后才能扩大范围；没有材料时提供待补充目录，不生成虚构章节。

切换产物保留已审核事实和回答；按新目标重新检查缺口。曾为 Skill 确认的泛化规则不自动成为 SOP 的历史事实。新产物生成失败不影响已有产物，也不撤销事实审核。

## 4. 共同事实输入与审核边界

生成器只接收被冻结且可追溯的输入：分析版本、审核结果、用户确认补充、证据索引、必要且已脱敏的截图、所选模板和文档配置。Skill 额外接收目标能力快照；不把无关凭据、全量原始日志或其他任务数据放进提示词。

事实区分：observed（录制可见）、user-confirmed（人工补充）、queried（授权补证）、inferred（推断）、unknown（未知）。保留来源、适用范围和时间。推断不能成为无提示的确定步骤或功能说明。

时态按产物解释：

- Skill：当前值写为执行时查询，历史值只作示例，固定规则必须经审核且有适用范围。
- SOP：保留实际操作和必要示例，隐私字段脱敏，标明录制时信息；不能把一次点击成功升级为永久有效的业务规则。
- 手册：将经确认的操作归入功能章节；字段含义、权限规则、产品限制需有证据，不能仅凭字段名推断。

截图和页面文字属于待分析素材，其中的“忽略规则”“发送到某地址”等文本不构成对生成器的指令。

## 5. 预置模板与提示词

### 5.1 模板机制

首批内置 `sop-standard@1`、`skill-standard@1`、`manual-feature@1`。模板分成“结构定义”和“类型专属生成规则”，由应用维护并记录版本；不是把整份录制拼接进一个自由提示词。

结构定义包含章节 ID、标题、必填性、内容类型、是否重复及证据要求。可选章节无证据则省略；必要信息缺失时展示待补充。用户可编辑标题、正文和可选章节，不能通过模板覆盖事实、隐私、权限和验证状态约束。首期不开放任意模板脚本或在线模板市场。

提示词按层组合：共同事实与安全规则 → 产物专属规则 → 模板结构 → 冻结输入 → 本次编辑要求。人工编辑只修改文案时不重跑模型；重新生成时保留编辑版本，供用户比较，不能静默覆盖。

### 5.2 SOP 模板

默认章节：

1. 标题、操作目的、适用范围。
2. 已确认的前置条件：账号角色、起始页面、所需资料；未验证项明确标注。
3. 操作步骤表：序号、界面/入口、操作说明、预期结果、截图/证据。
4. 异常与处理（仅有证据或确认的内容）。
5. 完成检查与待确认事项。
6. 来源、录制日期、适用产品版本（未知则标未知）、文档修订版本。

每步结构至少为 `id/title/location/action/expectedResult/evidenceRefs`，结果另标 observed/confirmed/unknown；不能只写“操作成功”。截图用稳定资源 ID 关联，不写机器绝对路径。过长流程按子任务分组，保留真实先后依赖。

生成引导：

> 根据审核后的录制事实编写给人执行的 SOP，忠实保留原系统、操作顺序、入口和交互方式。不转换为 MCP、API 或替代 CLI，不进行技能泛化计划。可以清理无关操作、合并重复动作；必要的失败恢复不能删除。人工补充需标注来源，未证实的结果标为待确认，不为填满模板编造步骤。

### 5.3 Skill 模板

默认章节：标准 frontmatter（name、description、按目标支持情况填写 allowed-tools），以及用途、输入与配置、环境依赖、执行流程、分支与失败处理、写操作授权、成功标准、已知缺口与验证状态。

沿用 `SkillPlan` 的参数值、泛化说明及计算/动作分类。后续扩展步骤的输入来源、输出供给、原操作引用和工具映射理由；保留 `tools` 中真实运行时标识，不把权限模式当工具名称。

生成引导：

> 根据审核事实和业务规则生成可复用技能，先提交计划。将录制操作映射为目标环境确实可用、语义等价的能力，优先适合任务的原生工具或 CLI；UI 专属环节才使用已存在的浏览器能力。保留账号身份、回复线程、附件、数据范围和授权语义。不编造工具或未核实规则。固定值、运行时输入、历史示例分开；缺少依赖列为缺口。按批准计划生成正文，不执行业务写操作，不宣称已通过试运行。

例如“网页回复邮件”不能无说明地变为“新建邮件”。工具名称存在不等于语义或权限等价。Skill 文件不负责安装 MCP 或授权账号。声明的 allowed-tools 也不等于获得宿主授权。

### 5.4 使用手册模板

默认章节：

1. 手册目标、适用读者、产品/版本和覆盖范围。
2. 已有证据支持的访问方式与前置条件。
3. 导航与界面概览（可选，截图标注真实控件）。
4. 功能章节：功能目的 → 入口 → 操作步骤 → 已核实字段说明 → 结果/示例 → 注意事项。
5. 跨功能场景（可选，只组织已有步骤，不补造功能）。
6. 常见问题与限制（有依据才生成）。
7. 未覆盖功能、待补充内容、来源和版本记录。

目录项包含 `id/title/scope/evidenceRefs/coverage`，coverage 为 covered/partial/planned；planned 只显示“待补充”，不展开生成操作正文。目录批准不等于批准未知事实。

生成引导：

> 为目标读者按功能和场景组织使用手册，保留已确认的实际产品操作方式，不转换为 Agent 工具调用。只描述录制和补充材料覆盖的功能与字段含义。单次录制默认生成对应章节，不能声称涵盖整个产品。未知权限、错误原因和功能限制标记待核实；无证据的章节保留目录占位或省略。

## 6. 数据与持久化设计

以下是新增契约建议，不是现有字段声明：

| 契约 | 主要字段与职责 |
| --- | --- |
| `OutputKind` | sop / skill / manual；录制偏好另允许 undecided，生成时必须明确 |
| `OutputRequest` | artifactId、kind、templateId/version、语言、读者、范围；仅 Skill 带 architecture 与能力快照引用 |
| `SourceBinding` | analysisRevision、analysisConfirmationId、inputFingerprint、已审核增强版本、材料及证据修订引用；跳过增强可无增强版本 |
| `DocumentDraft` | kind、结构化 sections、证据引用、缺口、覆盖范围、用户编辑与来源；不复用 SkillPlan 表示 SOP/手册 |
| `ArtifactRevision` | artifactId、revision、request、sourceBinding、内容、状态、生成时间、审核时间、导出记录 |

建议目录为 `sessions/<id>/artifacts/<artifactId>/`，包含 `request.json`、`revisions/<n>.json` 和资源索引。保留现有 analysis、workflow、skill-plan.json、skill.json 的读写兼容；通过适配层接入新版产物，不在首期直接删除旧文件。

状态分离：内容状态 draft/reviewed，来源状态 current/stale，导出状态未导出/已导出。Skill 另记依赖核验结果和 executionVerified=false；SOP/手册不套用“可执行性验证”标签。仍有关键缺口的内容仅允许显式保存为草稿，文件首页保留缺口说明。

源分析、审核事实、材料或模板选择变化后，旧预览标记过期；Skill 能力快照变化只使依赖该快照的 Skill 过期，不使 SOP/手册失效。导出时比较冻结版本并原子保存；曾导出的旧版本保持可查看，不自动改写外部文件。

## 7. 校验、展示与导出

共同硬校验：类型和模板匹配、必填结构存在、证据引用有效、资源在允许目录、无未解释占位符、来源版本仍一致。素材文字需转义，Markdown 预览禁用原始可执行 HTML，导出路径和资源不能越界。

类型专项校验：

- SOP：步骤可排序、有操作入口和结果状态；模型新增但未确认的步骤标缺口；不得因选择 SOP 要求能力快照。
- Skill：校验工具标识与目标能力、参数来源和计划/正文一致性；无法自动判定语义等价时列为待审核，不宣称机器已保证一致。正文出现未批准的写操作或工具要阻止定稿。
- 手册：章节必须落在已批准范围；功能操作正文要有证据或确认来源，partial/planned 状态可见；不把推断的字段含义当产品事实。

首期统一支持 Markdown；SOP/手册含图片时导出 ZIP（文档 + assets 相对引用），无图片可直接导出 .md。Skill 导出标准 `<skill-name>/SKILL.md`，必要资源使用相对路径且显式列依赖。Word/PDF 是后续渲染适配，不承诺本期支持。

预览显示产物类型、范围、来源、草稿缺口及截图；Skill 额外显示依赖与“尚未业务试运行”。证据按需展开，不让原始日志淹没正文。所有导出只写文档文件，不产生邮件、提交表单等业务副作用。

## 8. 实施拆分

1. 共同规则：增加 OutputKind/manual，基础分析和澄清提示词按产物分流；保留旧数据默认值，不将 undecided 静默解释成 Skill。
2. 模板与文档层：新增版本化模板注册表、DocumentDraft、证据资源引用和确定性 Markdown 渲染器。
3. SOP 闭环：事实整理、编辑预览、草稿提示、导出及来源过期检查。
4. 手册闭环：范围选择、目录审核、覆盖标记、功能章节生成及导出。
5. Skill 加固：复用现有技能计划与生成器，增加映射理由、输入输出衔接、计划/正文审核，维持未试运行状态。

建议新增 `electron/documentbuilder/` 处理 SOP/手册，共享 `electron/builders/read-tools.ts` 的受控证据读取；新增 `electron/outputs/` 处理模板注册、版本与导出。不要将文档生成塞入 `SkillBuilder` 并伪造技能 frontmatter。

## 9. 验收用例

| 用例 | 通过标准 | 不通过示例 |
| --- | --- | --- |
| 同一段网页发邮件录制生成三类产物 | SOP 保留网页步骤；Skill 在有语义等价工具时提出映射计划；手册生成邮件功能章节 | 三者都生成 send_email 指令 |
| SOP/手册无 MCP 环境 | 可基于充分事实生成，缺少证据只标对应内容缺口 | 被能力快照缺失阻断 |
| Skill 缺少邮箱工具 | 明确依赖缺口；有已核验浏览器能力时可提出替代计划 | 编造工具、宣称已经发送 |
| 只录到点击发送、没有结果 | 描述点击事实，结果标未确认 | 写“邮件已成功送达” |
| 邮件回复映射为工具 | 保留线程、身份及附件语义，用户可审核 | 静默改成独立新邮件 |
| 单次录制生成手册 | 仅覆盖已演示功能，其他章节为待补充 | 补写管理员、权限、错误码等未知功能 |
| 深度分析按产物提问 | SOP 问必要操作歧义；Skill 问必要泛化规则；已知事实不重复问 | SOP 被要求选择 MCP 或回答无关循环规则 |
| 同源多产物与编辑 | 各自产物、修订及审核独立，重新生成保留人工编辑版本 | 生成 Skill 覆盖已有 SOP |
| 冻结输入变化 | 旧预览不能作为当前结果静默定稿，要求重新检查 | 使用过期事实导出且无提示 |
| 图片导出与隐私 | 脱敏资源可离线打开，引用有效，无本机绝对路径及目录越界 | 图片丢失或携带原始敏感数据 |
| Skill 内容生成完成 | 明示尚未业务试运行 | 把内容审核通过显示为执行验证通过 |

机制验收可用合成录制和固定模型响应检查分流、结构、版本和资源；内容质量验收再使用真实模型检查事实忠实度与工具映射。合成通过不替代真实模型质量验收，也不替代业务执行验证。

## 10. 首版实施记录（2026-10-17）

- `common/output.ts`：三类版本化模板、分流引导、文档结构/IPC 校验、证据与章节范围校验、确定性 Markdown 渲染。
- `electron/documentbuilder/`：文档生成器、手册目录审核、独立修订与历史读取、脱敏截图保管、来源过期阻断、草稿/审核状态、Markdown/ZIP 原子导出。
- `src/DocumentBuilderView.tsx`：读者和范围设置、基础分析确认、手册目录编辑确认、逐步骤编辑、截图选择与预览、审核与草稿导出、历史版本选择。重新生成创建新修订，不覆盖已保存编辑。
- 录制入口增加“使用手册”；生成页可选择三类产物。SOP/手册不经过技能计划和 MCP 环境门槛。深度分析仅在进入该阶段后启动，其提示词携带当前产物类型；基础分析保持事实中立。
- Skill 计划扩展 `sourceStepIds/mappingReason/inputSources/output`，并在界面提供映射与数据衔接编辑。在有审核上下文的新链路中，正文不得申请计划外权限或引用计划外 MCP 标识。
- 新增文档专项测试与隔离 DOM 验收脚本，分别通过 `npm run test:documents`、`npm run test:documents-ui` 执行；后者需用 `SKILL_RECORDER_JSDOM_MODULE` 指定本机 jsdom 模块，不引入产品运行依赖。

首版范围和限制：预置模板暂不提供任意章节结构定制；模板标题与正文可在生成结果中编辑。截图只采用现有受控材料索引中的脱敏图片，无可靠 OCR 时隐藏原图。文档当前提供纯文本 Markdown 预览、结构化编辑和图片预览，不执行原始 HTML。真实模型的事实忠实度和映射语义仍需人工审核；工具/权限字符串校验不等于完整语义证明。尚未组织真实业务试跑，也未提供 Word/PDF 导出。

## 11. 生成页与发布分享：v12 设计补充

日期：2026-10-17。**本节新增发布与分享的设计，不代表发布能力已经实现。** §2“止于文件导出”仍描述现有实现边界；下一期范围扩展为审核后发布。四阶段流程按本节执行；v11 的三阶段记录保留作历史参考。

[可点击页面设计稿](design/skill-generation-wireframes/index-v12.html) · [页面目录与截图](design/skill-generation-wireframes/v12/README.md)。设计中使用合成内容，不连接外部账户。

### 11.1 四阶段与完成标准

**原始素材确认 → 深度分析 → 生成 → 发布**。第四步页面标题使用“发布与分享”。保留前三步现有职责；用户可以只生成并导出，发布不是完成生成的强制条件。

| 阶段 | 页面目的 | 完成标准 | 阶段导航行为 |
| --- | --- | --- | --- |
| 原始素材确认 | 核对实际录制操作 | 基础事实形成并经用户核对 | 回看既有内容 |
| 深度分析 | 必要补证与规则澄清 | 当前材料确认；简单任务可明确跳过 | 回看结果，不因导航自动批准 |
| 生成 | 生成、编辑、审核三类产物 | 当前修订审核保存成功；有缺口可保存草稿 | 切换产物加载对应内容，不隐式生成 |
| 发布 | 选择渠道、核对目标与权限、分享成果 | 已确认远端对象、版本及链接 | 未就绪时说明阻断原因，不自动执行外部写入 |

阶段状态分开存储：生成可显示“待生成 / 生成中 / 草稿 / 已审核 / 需更新”，发布显示“未发布 / 发布中 / 已发布 / 有新版本 / 失败 / 结果待确认”。本地保存或文件导出不能把发布阶段标为已完成。某渠道发布失败也不撤销生成审核状态。

### 11.2 生成页面：当前实现与下一期交互

生成阶段的首次入口为三种制品选择：**SOP 操作说明 / 产品使用手册 / 通用 Skill**。不在此处展示 Scout、Cowork、Claude Code 专用格式、自动化或未上线平台。通用 Skill 使用 `agent-skill` 目标，平台安装与分发属于后续发布环节。录制前偏好不自动跳过制品选择；选择本身不触发模型调用，已保存内容可继续回看。

2026-10-17 最新调整：SOP 初始页仅保留“生成 SOP”主按钮，不显示自定义要求、读者/范围表单或来源勾选。点击即使用默认模板和当前可用事实生成；生成中只显示处理状态与停止按钮。生成完成后仍需编辑审核。使用手册的目录与范围设置不受此调整影响。以下旧版描述涉及 SOP 重复确认的部分以此约定为准。

当前调用链：`DocumentBuilderView → window.skillRecorder.document → DocumentBuilder.generate/runModel → AgentClient`。模型后端随智能处理配置选择：本地模式使用 Claude Code，API 模式使用已配置模型。不是固定写死某个 Claude 模型。

页面沿用暖白底、细边框卡片、25px 黑色标题、弱化模板元信息，底部固定主操作；技术生成规则收在“生成说明”。正文单层滚动，底栏不遮挡确认框；窄窗口折行，不缩小正文来塞导航。前两阶段设计沿用 v11。

| 产物 | 当前生成页顺序 | 模型调用点 | 应用侧动作 |
| --- | --- | --- | --- |
| SOP | 生成 SOP → 编辑与审核 | 一次文档生成任务；使用 `submit_document` 提交结构化正文，任务可能包含多轮模型往返 | 校验、保存修订、编辑、审核、渲染、导出 |
| 使用手册 | 适用读者 → 覆盖范围 → 来源确认 → 生成覆盖目录 → 审核目录 → 生成正文 → 编辑与审核 | 先 `submit_outline`，用户确认目录后再启动 `submit_document`；不是一次性生成全文 | 目录状态及证据校验、修订保存、编辑、审核、导出 |
| Skill | 目标环境 → 技能计划 → 计划确认 → 生成 → 预览保存 | 计划和正文生成沿用现有 Skill 链路 | 计划校验、工具映射检查、文件渲染与导出；不执行业务试跑 |

事实输入来自基础分析和当前已接受的增强事实，附读者、范围、版本化模板、证据引用及所需脱敏资源索引。当前文档生成 UI 要求用户勾选来源确认；现有实现未因此新增独立的服务端来源确认凭证。发布实施时须由后端检查实际审核、来源一致性和产物修订，不能仅信任 UI 勾选值。未审核增强不能混入确定事实，截图按稳定资源 ID 引用。

当前生成会话仅开放目录/文档提交工具，不开放业务发送或修改工具。SOP 和手册保留真实操作；只有 Skill 做执行方式翻译。人工改文案、保存、导出不调用模型。生成失败/取消保留之前已保存的版本，新生成不静默覆盖人工修订。手册未覆盖的章节只保留待补充项，不扩写无证据的功能。

产物切换：同一录制下 SOP、手册和 Skill 独立保存；在生成阶段切换到 SOP/手册立即显示对应生成页，切到 Skill/暂不确定展示相应选择入口；不能把目标置空而停留空白阶段。切换只读取已有修订，不自动请求模型，不替用户确认来源。已保存内容重新加载；未保存编辑属于临时态，下一期在离开时提供“保存草稿后切换 / 放弃修改 / 继续编辑”，不承诺当前实现已具备该保护。

下一期在审核成功后提供“下一步：发布与分享”；文档编辑页的主动作可合并为“确认并保存，去发布”，保存失败则留在原页。保留本地“导出文件”作为次要操作。生成中显示真实阶段、耗时与取消；不显示伪百分比，不把模型自报成功当成保存成功。

### 11.3 发布页信息架构

顶部四步导航，当前第四步高亮。保留产物选择器，使发布记录始终归属于当前产物，而非整条录制。页面标题“让这份成果被使用”，说明“选择一个去处，将已审核的版本发布给需要的人”。右上角“返回生成”。

桌面正文左侧为目的地及配置，右侧窄栏为本次发布摘要（标题、产物类型、审核修订、资源、使用方式、小型内容预览）。窄窗口将摘要放入“查看本次发布内容”折叠区，不能丢失核对信息。设计原型已提供窄屏折叠摘要。

目的地是三行可选择入口，不新增三个必经步骤：

| 渠道 | 主要用途 | 位置与权限 | 发布结果 |
| --- | --- | --- | --- |
| 飞书文档 | 团队协作、在线阅读 | 连接账号；选择文件夹；查询并展示继承权限，不自动扩大范围 | 文档对象、版本、真实可访问链接 |
| Wiki 知识库 | 规范沉淀、长期检索 | 选择已接入平台、知识空间和父页面；首个适配器建议飞书知识库 | 页面/节点对象及链接；Confluence 等另行适配 |
| Workmate 分享链接 | 将成果安装到工作区使用或查阅 | 工作区、分享范围、包类型、依赖声明；账户和权限由使用者自行授权 | 真实托管产物、固定包版本、安装分享页 |

SOP/手册发布到 Workmate 时作为**文档资源包**，不翻译成可执行技能；Skill 才生成适配 Workmate 的技能插件。文档资源包、插件宿主格式、资源阅读入口、托管和访问控制尚需接口验证，未接入时显示“待接入”并禁用发布，可导出文件。不能仅把 ZIP 改扩展名就宣称可安装。

渠道配置先显示账号身份和连接状态，再填写发布标题、目标位置、可见范围、发布方式（新建 / 更新已有发布）和资源选择。位置不默认选，权限不能写成默认公开。Workmate 若支持“持链接访问”也必须受工作区和服务端授权规则约束；链接本身不是访问权限。

底部确认框：“我已核对目标位置、可见范围及本次发布内容。”主按钮随渠道为“发布到飞书文档 / 发布到知识库 / 生成安装分享链接”。未选择必需目标、未连接、未确认、未审核、来源过期或适配不可用时禁用并显示具体原因；允许回到生成或本地导出。

### 11.4 发布审核和写入边界

1. 发布使用当前已审核、来源未过期、没有阻断缺口的固定修订。草稿可以导出且带标记，本期不开放草稿正式发布或生成可安装链接。
2. “已审核”与“执行已验证”分开。Skill 允许分享已审核但业务执行未验证的版本，安装页持续显示该标记、依赖和已知限制；格式校验通过不等于业务试跑成功。
3. 仅发送选定正文、必要且已脱敏的关联资源、模板和版本元信息。不得打包原始录屏、会话 JSONL、全量证据、凭据或本地绝对路径。发布前可展开逐项预览。
4. 生成会话没有发布工具。发布由应用侧适配器凭明确的用户操作执行；账户连接与权限不足分别处理。创建文档、上传截图、创建 Wiki 节点、托管安装包均属外部写入，只能在确认发布后开始。
5. 初次发布显示新建。更新已有发布时展示远端位置、上次发布版本与本次差异；用户显式确认后更新。远端被其他人编辑时先检查版本冲突，不整篇强制覆盖、不丢失人工修改。
6. 发布不会自动发送群消息、邮件或通知特定人员。成功后由用户复制链接；后续如增加“发送到群”属于独立且明确的动作。

### 11.5 发布状态、恢复与分享结果

| 状态 | 用户看到的内容 | 允许动作与约束 |
| --- | --- | --- |
| 未连接 | 具体渠道及账号连接要求 | 连接成功回到配置，不自动发布 |
| 发布中 | 真实的准备/上传/远端确认状态与耗时 | 查看记录；停止等待不承诺撤销已经发生的写入 |
| 成功 | 标题、渠道位置、可见范围、审核修订、时间、发布者、链接 | 复制链接、打开、管理权限、发布到其他位置、完成 |
| 明确失败 | 可读原因及修复入口；保留本地产物与目标配置 | 修复后显式重试，不重跑生成模型 |
| 结果待确认 | 请求超时，可能已在远端创建 | 先核对远端，不直接重发创建；核对前不显示成功 |
| 部分成功 | 文档已创建但部分截图未成功等实际状态 | 展示已有对象，重试缺失资源或清理草稿，不默默标为发布完成 |
| 有新版本 | 远端仍为旧修订，本地已有新审核修订 | 查看差异，显式更新；不因本地保存而同步 |
| 上游来源过期 | 发布记录继续可查，本地当前内容需更新 | 返回生成，重新审核；不把新内容自动同步到旧链接 |

成功页保留发布历史，同一产物允许发到不同目标。飞书/Wiki 权限管理跳转目标平台；应用不声称可撤销所有外部分享。Workmate 服务若支持停用链接，需二次确认；停用只阻止后续访问/安装，不能删除接收方已经安装的副本。原型中的 URL 为 `example.invalid`，不能作为真实发布成功证据。

### 11.6 建议数据与适配接口（未实施）

`Publication` 记录绑定 `recordingId/artifactId/revision/contentHash/sourceFingerprint`，包含 `channel/adapterId/target/remoteObjectId/remoteVersion/url/visibility/status/createdBy/publishedAt/updatedAt`。多次尝试另存 `attemptId/requestId/idempotencyKey/phase/error/receipt`；不把可用令牌写入发布清单。Skill 旧存储通过适配层生成稳定产物引用，不强行与文档共用尚不存在的字段。

应用侧适配器提供 `connectionStatus / listDestinations / inspectTarget / prepare / publish / inspectPublication / update`；`revoke` 仅在渠道支持时提供。`prepare` 完成格式与资源校验并给出将上传的内容清单，不先写远端。`publish` 使用已经确认的清单，绑定修订与摘要；校验失败要求重新确认，不能悄悄改发布内容。

提交前持久化 attempt；幂等键依据固定产物修订、渠道目标及操作生成。重复点击复用正在进行的请求；更新和新建使用不同操作标识。远端 API 不支持幂等时，必须通过请求关联及远端对象核对降低重复创建风险，不能承诺无条件 exactly-once。崩溃后先恢复发布记录并核对远端，不能直接重发未知请求。

发布链路不需要调用模型；若用户选择生成分享摘要，那是单独的可选模型能力，不得修改被发布正文或自动通知他人。

### 11.7 下一期验收门槛

- SOP → 手册 → SOP 切换，生成页不空白、不会自动调用模型；已有保存修订可恢复，未保存编辑有离开保护。
- 手册目录确认前不生成正文；保存审核失败不能进入已就绪发布状态。
- 未审核、来源过期、依赖格式不兼容、渠道未连接时给出明确阻断及恢复入口。
- 飞书/Wiki 的位置、权限与图片资源经真实适配器验证；Workmate 必须从分享页实际安装对应类型的资源，文档不能冒充技能。
- 同一审核修订发布后再编辑，不改变远端；显式更新检查冲突，保留发布历史。
- 重复点击、超时、崩溃和部分上传失败不会被误记为成功；重试先检查是否已有远端对象。
- 分享包检查不含原始录屏、会话日志、凭据及本机路径；不会因发布或复制链接自动给其他人发送消息。
- 视觉实现与 v12 设计稿一致，正文单层滚动，窄窗口保留全部必要的核对信息。
