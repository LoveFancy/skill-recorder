# 离线 Chrome 插件：首版

## 安装和使用

1. 打开新版技能录制器，展开首页的 **Chrome 插件**，点击 **打开插件目录**。
2. 在 Chrome 打开 `chrome://extensions`，开启开发者模式，选择 **加载已解压的扩展程序**，选中应用打开的 `chrome-extension` 目录。首次需要手动完成；不会静默修改 Chrome 的安全设置。
3. 在普通 HTTP/HTTPS 网页中点击插件图标，点击 **采集当前标签页**。只授权当前站点；跨到不同站点时重新授权绑定。
4. 桌面录制源选择此 Chrome 窗口或所在屏幕，开始录制。插件显示“录制”，桌面首页显示累计采集条数。
5. 结束录制后正常分析。真实浏览器操作与截图、语音、手动框选/点击/截取标记共同进入分析输入。

应用将插件复制到用户数据目录的固定子目录，原生助手也安装在用户目录。安装包内有全部文件，无需安装 Node、Python 或 Go。更新应用后，Chrome 扩展页面点击 **重新加载**；首版不会自动重载运行中的插件。

## 采集内容

- 真实点击、输入（350ms 合并）、选项/勾选变化、提交、滚动、导航和 SPA 路由变化。
- 元素标签、可访问名称、角色、少量目标文字、CSS/角色定位候选及 CSS 候选的唯一性。
- 页面 URL（去掉账户、查询参数及片段）、标题、标签页/文档/iframe 标识、视口/滚动信息及采集时间。
- 密码、隐藏、文件、密钥/验证码等敏感字段不采集值、文字或定位内容；只保留已遮蔽的控件类型。普通输入可能含个人信息，发给模型前仍经过现有敏感扫描；嵌套字段也纳入扫描。
- 点击位置、元素矩形为 **CSS 视口坐标**，不是桌面截图像素，不直接画到桌面截图上。

内容脚本只在当前录制、已绑定且获授权的文档中记录前台真实事件，忽略脚本合成的点击。延迟输入保留实际采集时间及焦点状态，防止切换标签页或结束录制导致最后一次输入丢失。未录制时不持久化操作内容。插件和本机桥不访问外网；网页自身及配置的模型接口可能联网。

## 如何进入轨迹

```text
真实 Chrome 事件 → Native Messaging 独立程序 → 本机 socket / Windows 命名管道
→ 会话 events.jsonl（browser.action）→ bundle.json / 截图关联
→ get_browser_actions → analysis.json 步骤的 browserEventIds
→ Skill / 自动化生成的 get_browser_targets
```

- `events.jsonl` 保留完整的浏览器事件。`epoch` / `t` 使用采集时间，`receivedAt` 单独记录到达时间。
- 只有事件写入回调成功后才 ACK；插件保留未确认队列、重传，桌面按 `eventId` 去重。ACK 表示数据已交给文件系统，不承诺突然断电后的 fsync 持久性。
- 每次录制使用新的会话 ID。过期会话、非法时间或格式被拒绝。
- 正常结束先停止各文档采集并同步剩余输入，最多等待 2.5 秒。超时会显示提示，不能承诺最后事件完整。
- 浏览器事件参与现有截图抽取/时间关联。首版不额外逐点击截屏，也不保证每次点击都有独立截图。
- 模型提交前必须读完所有浏览器事件页，每页最多 100 条；实质操作必须归到步骤的 `browserEventIds`，遗漏或引用未知 ID 会被拒绝。允许把相关操作合为一步，允许忽略仅滚动的事件。
- 下游 Skill/自动化生成可以通过步骤引用重新读取定位候选，文本经过敏感扫描和遮蔽。首版采集并提供输入，**没有自动回放执行器**。

## 本机连接和分发

- MV3 扩展固定 ID：`hodlffjdgjideoajfnnmocfjckjjpmgp`，通过公开 `manifest.key` 保持稳定，无私钥依赖。
- Native host：`com.skillrecorder.browser`，允许来源只包含该扩展 ID。
- macOS：用户级 Chrome Native Messaging manifest + 权限 0600 的 Unix socket。
- Windows x64：HKCU Native Messaging 注册 + 命名管道；无需管理员权限。连接使用随机本机令牌验证。
- 同时只支持一个 Chrome 插件连接和一个绑定标签页。第二个连接取代第一个；多 Chrome 配置文件并行录制未实现。
- 队列上限 2000 条，达到上限显示采集错误；单会话桌面去重上限 100000 条。断连期间暂停新采集，已缓存事件在恢复同一会话时重传。不会因此终止桌面录制。

## 已知边界

- 首版由用户确认“绑定标签页”和桌面录制源一致；没有自动验证 Chrome 窗口 ID 与原生窗口 ID 的映射。请选择正确来源。不要用浏览器证据推断另一个应用窗口的画面。
- 同源 iframe 已验证；跨源 iframe 必须另有站点授权，否则不可采集。不会擅自请求全站点权限。
- 开放 Shadow DOM 的点击可以取得实际目标，但候选标注 shadow 范围，不认为全页面唯一；闭合 Shadow DOM 和复杂自绘控件定位能力有限。
- 不支持 Chrome 内部页、扩展商店、PDF 内部查看器、文件页及隐身模式。
- 角色定位是候选，CSS 唯一性仅在录制时、当前文档内成立；重放需要重新验证。真实点击事件不等于操作结果成功。
- Windows x64 原生助手已交叉编译；**Windows 机器上的 Chrome/命名管道端到端验证尚未完成**。macOS 实际 Chrome 完整链路已验证。

## 开发和验证

需要 Go ≥1.26.1，仅构建者需要。`SKILL_RECORDER_GO` 可指定 Go 可执行文件；本机开发也支持缓存路径 `~/.cache/skill-recorder/toolchains/go/bin/go`。

```sh
npm run build             # 构建三种原生助手以及应用
npm test
npm run typecheck:evals
npm run test:browser:chrome  # macOS Chrome 155+，临时隔离配置，仅本机测试网页
```

真实 Chrome 冒烟测试自动加载相同内容脚本/worker，测试 manifest 只预授权临时 loopback 站点。使用独立 Chrome profile；暂时注册测试 native host，结束恢复原注册。不要在正在录制时运行。它不发送模型 API 请求，验证的是进入分析工具、提交约束、轨迹持久化及下游定位工具的完整数据链路；模型对意图的理解质量取决于配置的模型。

自动测试包含原生助手帧协议、落盘后确认、重传去重、过期会话拒绝、最后输入同步、结束后排除、嵌套敏感字段遮蔽、超过 100 条事件分页及分析遗漏拦截。真实 Chrome 测试涵盖真实点击、输入、选择变化、SPA、同源 iframe、密码排除、截图时间关联、分析事件引用保存及下游定位信息读取。
